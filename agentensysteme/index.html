Agentensysteme verstehen – nicht nur einzelne Agenten.

Ein moderner KI-Agent ist häufig kein isoliertes Modell. Er kann aus Modellen, Tools, Memory, Datenquellen, Protokollen, Subagenten und menschlichen Kontrollpunkten bestehen. AgentenIndex baut deshalb zusätzlich zur Produktreferenz eine evidenzbasierte Systemebene auf.

DirektantwortWas ist die Agentensystem-Ebene?

Sie beschreibt, woraus ein agentisches System besteht und wie seine Teile zusammenarbeiten: Agenten, Frameworks, Modelle, Tools, Memory, Protokolle, Datenquellen, menschliche Rollen und Governance. Jede dokumentierte Beziehung benötigt explizite Evidenz.

Warum jetzt

Produktlisten reichen für die nächste Agentenphase nicht aus

Wenn ein Agent Aufgaben an Subagenten delegiert, unterschiedliche Modelle aufruft, über MCP oder A2A kommuniziert, persistenten Zustand hält oder vor kritischen Aktionen menschliche Freigaben benötigt, liegt ein wesentlicher Teil seiner Leistungsfähigkeit und seines Risikos zwischen den Komponenten. Genau diese Beziehungen werden zur eigenen Prüfebene.

Der DeepMind-Institute-Essay Artificial Symbiotic Intelligence liefert dafür einen aktuellen konzeptionellen Rahmen. Er ist keine Produktquelle. Deshalb nutzt AgentenIndex ihn zur Taxonomieentwicklung, aber niemals als Beleg dafür, dass ein konkretes Produkt eine bestimmte Fähigkeit besitzt.

Systemtaxonomie

Fünf Ebenen sauber trennen

Agent

Ein konkreter agentischer Akteur oder ein Produkt mit eigener Aufgabe und eigenem Handlungsspielraum.

Agent Framework / Harness

Eine technische Laufzeit oder Orchestrierungsschicht zum Erstellen, Ausführen oder Koordinieren von Agenten.

Agent Component

Modell, Tool, Memory, Skill, Connector, Runtime, Wissensbasis, Protokoll oder Datenquelle.

Agent System

Mehrere Agenten und Komponenten, die für einen Prozess oder ein gemeinsames Ziel koordiniert zusammenarbeiten.

Agent Institution

Ein Agentensystem mit expliziten Rollen, Regeln, Freigaben, Eskalation, Verfahren und Governance.

Die Beziehungen werden selbst zu Daten

AgentenGraph kann neben klassischen Produkteigenschaften Beziehungen abbilden: uses model, uses tool, uses memory, communicates via, delegates to, hands off to, requires approval from, member of, governed by und operated by.

Keine Relation durch Vermutung

Eine Plattformfunktion wird nicht auf einen Agenten übertragen. Beziehungen werden nicht transitiv abgeleitet. Unterstützt ein Framework beispielsweise A2A, folgt daraus nicht automatisch, dass jeder darauf gebaute Agent A2A-Client oder A2A-Server ist.

AgentenWache

Monitoring muss künftig Systemänderungen erkennen

Für agentische Systeme sind nicht nur neue Features relevant. Ebenso wichtig sind Änderungen an Modell, Toolrechten, Memory, Delegation, Protokollen, Human Approval, Hosting, Audit, Identität, Rollback und Betriebsgrenzen. Diese Kategorien sind deshalb im Systemmodell als eigene Change-Typen vorgesehen.

AgentenWache erzeugt daraus weiterhin keinen automatischen Produktfakt. Ein erkannter Quellenwechsel ist Prüfbedarf; erst verifizierte Evidenz darf den Graph, ein Profil oder eine Freigabeentscheidung verändern.

AgentenFreigabe

Die richtige Frage lautet: Ist dieser konkrete Systemzustand freigabefähig?

Ein Produktlogo ist keine ausreichende Freigabeeinheit. Für Unternehmen sind mindestens Identität, Toolrechte, Delegation, Human Approval, Audit und Tracing, Rollback und Stop, Memory und Zustand, Daten und Hosting, Security Controls sowie Betriebsgrenzen relevant.

Das neue AgentenFreigabe-Prüfschema verbindet diese Dimensionen mit Field-Level-Evidenz und hält unbekannte Merkmale bewusst offen. Es gibt keinen universellen 0–100-Score.

Strategischer Wert

Warum diese Ebene AgentenIndex schwerer austauschbar macht

Ein einfacher Katalog lässt sich von Suchmaschinen oder Sprachmodellen schnell zusammenfassen. Eine versionierte Evidenzbasis mit feldgenauen Quellen, Historie, Systemkomponenten und belegten Beziehungen ist dagegen ein eigenständiger Datenbestand. Der Mehrwert liegt dann nicht nur im Text einer Seite, sondern in der nachvollziehbaren Struktur darunter.

Das Ziel ist deshalb nicht, möglichst viele Agentennamen zu sammeln. AgentenIndex soll zunehmend beantworten können: Woraus besteht ein System? Was darf es? Womit kommuniziert es? Was delegiert es? Wo greift der Mensch ein? Welche Kontrollen sind belegt? Was hat sich wann geändert?

FAQ

Häufige Fragen zu Agentensystemen

Was ist ein Agentensystem?

Ein koordinierter Verbund aus einem oder mehreren Agenten und Komponenten wie Modellen, Tools, Memory, Datenquellen, Protokollen und menschlichen Rollen.

Was unterscheidet Agent und Framework?

Der Agent ist der konkrete Akteur oder das Produkt mit einer Aufgabe. Framework oder Harness stellt Laufzeit, Orchestrierung oder technische Bausteine bereit.

Warum sind Beziehungen wichtig?

Weil Delegation, Toolzugriff, Protokolle, Memory und Freigabepunkte einen erheblichen Teil des tatsächlichen Systemverhaltens bestimmen können.

Leitet AgentenIndex Relationen automatisch ab?

Nein. Nur explizit belegte Relationen werden dokumentiert. Unknown bleibt unknown.
