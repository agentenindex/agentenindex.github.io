n8n führt wiederverwendbare Agents als eigenen Produkttyp neben Workflows ein

n8n führt einen eigenen Agententyp ein, der mit Modell, Tools und bestehenden Workflows konfiguriert wird und über Slack, Zeitplan oder andere Workflows aufgerufen werden kann.

Betroffener Agentn8n Agents · n8n →
Direktantwort

n8n führt Agents als eigenständige, wiederverwendbare Einheit neben klassischen Workflows ein. Ein Agent erhält ein Modell sowie freigegebene Tools und Workflows und kann unter anderem über Slack, Zeitpläne oder den neuen Message-an-Agent-Node angesprochen werden.

Vorher

AgentenIndex führte n8n bereits als Plattform für agentische Workflow-Automation; ein eigener wiederverwendbarer Agententyp war noch nicht als separates Produktkonzept beschrieben.

Jetzt

n8n dokumentiert Agents als eigenständige, wiederverwendbare Einheit neben Workflows, mit Modell, Tools, Workflows und mehreren Aufrufwegen.

n8n hat am 25. September 2026 einen neuen Produkttyp namens Agents vorgestellt. Ein Agent wird mit einer Aufgabe, einem Modell sowie den Tools und Workflows konfiguriert, die er verwenden darf. n8n beschreibt Agents als wiederverwendbare Einheiten für offene oder dialogartige Aufgaben, bei denen ein fest verdrahteter Workflow schnell unübersichtlich werden kann.

Die neue Struktur sitzt bewusst neben den bestehenden Workflows. Ein Agent kann vorhandene n8n-Workflows als Tools verwenden; umgekehrt kann ein Workflow mit dem neuen „Message an Agent“-Node einen Agenten aus einem laufenden Prozess heraus aufrufen. Damit wird die Trennung zwischen deterministischer Workflow-Logik und agentischer Entscheidung expliziter.

Der gleiche konfigurierte Agent kann laut n8n über mehrere Einstiegspunkte genutzt werden: im Slack-Dialog, nach Zeitplan oder aus einem anderen Workflow heraus. Für AgentenIndex ist das eine relevante Architekturänderung, weil der Agent nicht nur als einzelner Schritt in einem Workflow gedacht ist, sondern als eigenständig adressierbare Einheit mit festgelegtem Modell- und Tool-Umfang.

Die Ankündigung macht zugleich deutlich, wo Governance ansetzen muss. Welche Aktionen ein Agent tatsächlich ausführen kann, hängt von den freigegebenen Tools, Workflows und Credentials ab. AgentenIndex leitet aus dem Launch daher keine pauschale Aussage zu Hosting, Datenresidenz oder menschlicher Freigabe ab. Diese Eigenschaften müssen weiterhin feldgenau durch separate Primärquellen belegt werden.

Für Teams kann das neue Modell die Wiederverwendung vereinfachen: Statt agentische Logik mehrfach in verschiedenen Automationen nachzubauen, lässt sich ein definierter Agent an mehreren Stellen ansprechen. Entscheidend bleibt, seine Werkzeuge klein zu halten, Credentials nach Least-Privilege zu vergeben und Fehler- beziehungsweise Eskalationspfade klar zu definieren.
